# prtseek

deepseek 계열 모델로 구동되는 CTF Agent.

이 프로젝트는 [RuoJi6/ARTEX](https://github.com/RuoJi6/ARTEX) 를 기반으로 2차 개발한 것이며, 원본 프로젝트는 [Autumn-27/ARTEX](https://github.com/Autumn-27/ARTEX) 이다. Go 모듈 경로 `github.com/Autumn-27/artex` 와 AGPL-3.0 라이선스를 유지한다.

## 프로젝트 개선점

ARTEX 와 비교해 prtseek 는 SRC 버그 헌팅 등 CTF 범위에 포함되지 않는 기능과 코드를 삭제하고, 원래의 침투 테스트 Agent 워크플로를 CTF 워크플로로 바꿨다. CTF web 환경에서 전통적인 침투 테스트 agent 는 흔한 기법을 시도한 뒤 테스트를 멈추고 사용자에게 더 많은 공격 표면을 요구하는 경우가 많아, 단일 복잡 환경을 장시간 자율적으로 연구하는 능력이 부족하다.

이 프로젝트는 CTF 에서 단일 대상에 4시간 이상 매달리는 사용 상황에 맞춰 특별히 최적화했다. prtseek 1.0 버전을 공개한 당일, 우리 팀은 제10회 창왕베이(强网杯) 천기(天基) 네트워크 보안 트랙 CTF 부문에서 3위를 차지했다:

![image](./docs/images/qwb-2026-tianji-ranking-cropped.png)

이 프로젝트는 deepseek v4.1 flash 모델에 맞춰 최적화했으므로, 다른 모델을 사용하면 최상의 효과를 내지 못할 수 있다.

## 빠른 시작

사이드바에는 **Agents 관리, LLM 관리, 도구 관리, 설정, 파일 작업 공간, 스킬 라이브러리** 가 있으며, 왼쪽 위 브랜드를 클릭하면 대화로 돌아간다. 도구 관리에서는 시스템 도구를 확인하고 바인딩할 수 있으며, shell, command, Python script, HTTP 사용자 정의 도구를 생성, 테스트, 수정, 활성화/비활성화, 바인딩, 삭제할 수 있다.
### Windows

소스에서 처음 실행하려면 Go 1.26.10 이상, Node.js 22, npm 이 필요하며 PATH 에 추가되어 있어야 한다. `start-prtseek.cmd` 를 더블 클릭하거나 다음을 실행한다:

```powershell
.\start-prtseek.cmd
```

처음에는 프론트엔드 의존성을 자동 설치하고 프론트엔드를 내장한 백엔드 프로그램을 빌드한 뒤 <http://127.0.0.1:18787/chat/> 를 연다. 서비스는 백그라운드에서 실행되며, 다시 열면 빌드를 검증하고 같은 인스턴스를 재사용한다. 소스 디렉터리에서는 `.dev/prtseek.exe` 만 사용하므로 루트 디렉터리의 오래된 exe 가 새 빌드를 가리지 않는다. 소스나 프로그램 지문이 일치하지 않으면 다시 빌드하며, 기존 서비스가 실행 중이면 업데이트가 필요하다고 명확히 알려 주고 이전 버전을 조용히 열지 않는다.

```powershell
# 소스를 수정한 뒤 다시 빌드하고 시작
powershell -NoProfile -File .\start-prtseek.ps1 -Build
# git pull 후 업데이트: 먼저 빌드에 성공한 뒤, 이 설치 디렉터리의 기존 인스턴스를 중지하고 새 버전을 시작
.\update-prtseek.cmd
# 브라우저를 자동으로 열지 않음. 포트 변경 가능
powershell -NoProfile -File .\start-prtseek.ps1 -NoBrowser -Port 18787 -ProxyPort 18788
```

`go.mod` 가 없는 배포 패키지는 루트 디렉터리의 `prtseek.exe` 를 바로 사용하며 Go/Node.js 가 필요 없다. 패키지에 포함된 `.build.json` 과 전체 시작 스크립트를 그대로 둔다. 기존 `start.bat`, `start-personal.cmd` 진입점도 같은 시작 구현으로 계속 전달된다. 업데이트하면 진행 중인 연구가 종료되므로 먼저 작업을 끝내거나 화면에서 중지한다. 컴파일에 실패하면 실행 중인 기존 서비스가 유지된다. 서비스를 완전히 중지하려면 작업 관리자에서 해당 설치 경로의 `prtseek.exe` 를 종료하면 된다.

### Linux / macOS

```bash
bash install.sh       # 현재 소스에서 한 번 빌드해 ./prtseek 생성
sh start.sh          # 포그라운드 실행, 기본 HTTP :8787, 프록시 127.0.0.1:8788
```

<http://localhost:8787/chat/> 에 접속한다. 소스 설치의 `start.sh` 는 빌드 지문을 확인하며, 소스가 바뀌면 후보 프로그램을 먼저 성공적으로 빌드한 뒤 교체한다. 업데이트 절차: 기존 실행기/시스템 서비스 중지 → `git pull --ff-only` → `bash update.sh` → `sh start.sh`(또는 시스템 서비스 재시작). 이전 버전에서 처음 업그레이드할 때도 반드시 기존 프로세스를 중지해야 하며, 새 버전의 디렉터리 잠금이 같은 설치의 중복 실행을 막는다. 배포 패키지 실행에는 빌드 도구가 필요 없다. 처음 로그인할 때 화면 안내에 따라 비밀번호를 설정한 뒤 시스템 설정에서 모델을 구성한다.

### Docker

```bash
docker compose up --build -d
docker compose logs -f prtseek
docker compose down
```

Dockerfile 은 현재 소스에서 프론트엔드와 백엔드를 빌드한다. Compose 에는 `prtseek` 서비스 하나만 있으며 <http://localhost:8787/chat/> 로 접속한다. 데이터베이스와 기타 실행 데이터는 호스트의 `data/` 에 매핑된다. `.env` 는 선택 사항이며 변수 예시는 [.env.example](.env.example) 를 참고한다.

컨테이너를 업데이트하려면 `git pull --ff-only` 후 `docker compose up --build -d --force-recreate` 를 실행한다. 기존 이미지를 재시작하는 것만으로는 프로그램이 업데이트되지 않는다. 모든 빌드는 기본적으로 `VERSION` 에서 버전을 읽으며, `/api/health` 의 `build_id` 를 `/build-info.json` 과 대조할 수 있다. 이미 열린 페이지는 서비스 빌드 변경을 감지하면 새로 고침을 안내하고, 사용자가 직접 새로 고칠 때까지 보내지 않은 입력을 보존한다. 페이지와 RSC 파일은 영구 캐시가 금지되며, 콘텐츠 해시가 붙은 정적 리소스는 캐시할 수 있다.

업데이트 감지 기능이 없는 이전 페이지에서 처음 업그레이드할 때는 감지 컴포넌트를 불러오도록 한 번 직접 새로 고쳐야 한다. 이후 버전 변경부터 자동으로 안내가 표시된다.

업그레이드 시 기존 설치의 `data/`, `config.json`, 모델 설정이 유지되므로, 데이터 디렉터리를 새 빈 디렉터리로 바꾸지 않는다. Windows 업데이트 진입점은 같은 설치 디렉터리의 프로세스만 관리하며, 다른 프로세스가 포트를 점유하면 오류를 낸다.

## CTF 와 Agent 분배

입력창에서 여러 첨부 파일을 클릭하거나 끌어다 놓을 수 있다. 파일은 대화별로 격리된 작업 디렉터리에 들어가고, Agent 는 읽을 수 있는 절대 경로를 받는다. `triage` 는 자료를 정리하고, `command` 는 `delegate_agents` 로 서로 다른 관점에서 2–6개의 `solver` 를 병렬 실행할 수 있다. 수렴된 결과는 `writeup` 에 넘겨 EXP 와 `WRITEUP.md` 를 생성할 수 있다. 하위 대화는 상위 대화의 실제 모델 설정을 상속하며, 별도 사이드바에 실시간 진행 상황과 보기 링크가 표시된다.

Agent 관리에는 기본 CTF Agent 네 개만 표시된다. 역할마다 프롬프트, 모델, 턴 수, 도구 표시 여부를 조정할 수 있다. 새 대화는 기본 역할 중에서 진입점을 선택할 수 있으며, 협업 관계는 기본 역할 프롬프트와 분배 결과로 정의된다.

`triage`, `command`, `solver` 의 신규 설치 기본 시간 예산은 4시간(14400초)이다. 기존 Agent 의 사용자 설정은 유지되므로 업그레이드 후 Agents 관리에서 시간과 턴 수를 확인한다. `writeup` 의 기본값은 30분이다. 하위 작업은 상위 작업의 마감 시각을 상속하면서 자체 예산도 지키며, 연구를 이어가도 타이머가 초기화되지 않는다.

모델이 일반 텍스트로 끝내는 것은 단계 체크포인트일 뿐이다. 연구 역할은 반드시 `research_status` 로 이번 턴의 증거가 뒷받침하는 완료 결론이나 구체적인 외부 차단 요인을 제출해야 하며, flag 를 얻지 못한 것 자체는 차단 요인이 아니다. 압축 후에는 현재 연구 상태를 다시 주입해 증거, 실패한 경로, 다음 단계를 유지한다. 중단 후 대화를 이어갈 수 있으며 도구의 부수 효과를 자동으로 재실행하지 않는다. 종료 검사가 세 번 연속으로 새 도구 증거 없이 끝나면 성공으로 허위 보고하지 않고 정체로 표시한다.

메인 작업과 하위 작업은 한 턴 전체에서 기본적으로 200회의 논리적 모델 요청(압축 포함)을 공유하며, 무한히 실행되지 않는다. 장시간 작업은 시작 전에 `prtseek_CTF_MODEL_CALL_LIMIT=2000`(범위 1–100000)을 설정할 수 있고, 대화 개요에 실제 제한이 표시된다. Windows PowerShell 에서는 `$env:prtseek_CTF_MODEL_CALL_LIMIT='2000'` 을 설정한 뒤 같은 터미널에서 업데이트 진입점을 실행하고, Docker 는 `.env` 에서 설정한다. 시간, 턴 수, 호출 예산, 사용자 중지, 실제 외부 차단 중 가장 먼저 도달한 조건이 적용된다. 수 시간에 걸친 연구 지속은 모의 시계와 프로토콜 회귀로 검증했으며, 실제로 수 시간 동안 문제를 푼 것이나 flag 획득을 보장하는 것은 아니다.
