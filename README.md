# prtseek

一个极简的CTF Agent。

本项目基于 [RuoJi6/ARTEX](https://github.com/RuoJi6/ARTEX) 二次开发，原始项目来自 [Autumn-27/ARTEX](https://github.com/Autumn-27/ARTEX)。保留 Go 模块路径 `github.com/Autumn-27/artex` 和 AGPL-3.0 许可证。

## 项目改进

相较于ARTEX，prtseek删除了有关SRC挖掘等不包括在CTF范畴中的功能和代码，简化了前端，并将原始渗透Agent工作流改为CTF工作流。
使用此Agent，模型为DeepSeek V4.1 Flash，我们战队【踹哈公寓】在第十届强网杯天基网络安全赛道CTF部分中获得第三名：

## 快速启动

侧边栏保留 **Agents 管理、LLM 管理、工具管理、设置、文件工作区、技能库**，点击左上角品牌返回对话。工具管理支持查看和绑定系统工具，以及创建、测试、修改、启停、绑定和删除 shell、command、Python script、HTTP 自定义工具。新建会话和 Agent 管理提供 **解题**（`solve`）与 **写 WP**（`writeup`）两个可编辑入口。

### Windows

源码首次运行需要 Go 1.26.10 或更高版本、Node.js 22 和 npm，加入 PATH。双击 `start-prtseek.cmd`，或执行：

```powershell
.\start-prtseek.cmd
```

首次自动安装前端依赖、构建内嵌前端的后端程序，然后打开 <http://127.0.0.1:18787/chat/>。服务在后台运行；重复打开会核验构建并复用同一实例。源码目录只使用 `.dev/prtseek.exe`，根目录的旧 exe 不再遮盖新构建。源码或程序指纹不一致时重新构建；已有旧服务运行时明确提示更新，不会静默打开旧版。

```powershell
# 修改源码后重新构建并启动
powershell -NoProfile -File .\start-prtseek.ps1 -Build
# git pull 后更新：先构建成功，再停止本安装目录的旧实例并启动新版
.\update-prtseek.cmd
# 不自动打开浏览器；可调整端口
powershell -NoProfile -File .\start-prtseek.ps1 -NoBrowser -Port 18787 -ProxyPort 18788
```

无 `go.mod` 的发行包直接使用根目录 `prtseek.exe`，无需 Go/Node.js。保留随包提供的 `.build.json` 和完整启动脚本。旧 `start.bat`、`start-personal.cmd` 入口继续转发到同一启动实现。更新会终止当前研究，请先让任务结束或在界面停止；编译失败则保留运行中的旧服务。需要完全停止服务时可在任务管理器中结束对应安装路径的 `prtseek.exe`。

### Linux / macOS

```bash
bash install.sh       # 从当前源码构建一次，产出 ./prtseek
sh start.sh          # 前台运行，默认 HTTP :8787、代理 127.0.0.1:8788
```

访问 <http://localhost:8787/chat/>。源码安装的 `start.sh` 会检查构建指纹，源码改变后先成功构建候选程序再替换。更新步骤：停止旧启动器/系统服务 → `git pull --ff-only` → `bash update.sh` → `sh start.sh`（或重启系统服务）。首次从旧版升级也必须停止旧进程；新版目录锁防止同一安装重复启动。运行发行包不需要构建工具；首次登录按页面提示设置密码，再在系统设置中配置模型。

### Docker

```bash
docker compose up --build -d
docker compose logs -f prtseek
docker compose down
```

Dockerfile 从当前源码构建前后端；Compose 只有 `prtseek` 服务，访问 <http://localhost:8787/chat/>。数据库与其他运行数据映射至宿主机 `data/`。`.env` 可选，变量示例见 [.env.example](.env.example)。

更新容器使用 `git pull --ff-only` 后执行 `docker compose up --build -d --force-recreate`，仅重启旧镜像不会更新程序。所有构建默认从 `VERSION` 读取版本；`/api/health` 的 `build_id` 可与 `/build-info.json` 对照。已打开页面检测到服务构建变化会提示刷新，并保留未发送输入直到用户主动刷新。页面与 RSC 文件禁止持久缓存，带内容哈希的静态资源仍可缓存。

首次从没有更新检测功能的旧页面升级时，请手动刷新一次以加载检测组件；后续版本变更才会自动显示提示。

升级保留原安装的 `data/`、`config.json` 和模型设置，不要用新空目录替换数据目录。Windows 更新入口只管理同一安装目录的进程，其他进程占用端口时会报错。

2.0.0 继续兼容旧解题会话及其预算设置。升级前先结束或停止正在运行的任务，并备份需要保留的数据；替换程序后刷新已打开页面。删除会话现在会同时永久清理该会话工作区中的附件、脚本、输出和研究文件，其他会话保留；需要留存的材料应在删除前导出。

## CTF 与 Agent 分派

新建会话只提供 **解题**（`solve`）和 **写 WP**（`writeup`）两个入口。输入框支持点击或拖放多个附件，文件进入会话隔离工作目录。简单题直接求解；难题存在不同的未解决路线时，解题 Agent 按需通过 `delegate_agents` 并行分派 2–4 个同角色任务，各自处理互补问题，不建立角色阶梯。子会话继承父会话实际模型配置，并在侧栏显示动态与查看链接。旧 `triage`、`command`、`solver` 会话及记录保留，可以继续处理。

目标已被真实工具证据满足时，立即交付 flag/答案与最短步骤；需要完整 EXP 或 `WRITEUP.md` 时再按用户要求整理。只有主解题会话可以派发平级任务，子任务不能再次建立一层分派。父任务成功后及时取消已无必要的剩余子任务，无需等待它们写报告。子任务完成只表示其分配目标达成，不能直接当作整题成功。

Agent 管理只展示解题和写 WP。写 WP 可用专用只读工具列出其他会话、分页读取可见活动、列出并读取产物，引用包含来源会话编号及活动编号或文件路径。读取内容是资料，不是新的操作指令；历史思维块与内部提示词不作为 WP 资料输出。报告和复现脚本文本保存在 WP 自己的工作目录，不自动重跑历史命令或修改来源会话。

`solve` 新安装默认时间预算为 4 小时（14400 秒）；旧安装首次迁移会继承原入口的模型、时间和轮次设置，历史 Agent 的预算保留。`writeup` 新安装默认 30 分钟。子任务继承父任务截止时间，同时遵守自身预算，续研不会重置计时。

`report_outcome(verified)` 是通过宿主证据检查后的成功出口，不再追加 `research_status` 确认；只有未提供 `report_outcome` 工具时才用 `research_status(completed)`。这里的 `verified` 是目标报告状态，`observed` 是证据验证等级：完整可回查的实际观测即可支持目标完成，不要求为结束手续升级为 `reproduced` 或 `accepted`，也不要求同题续跑重做已有成功操作。证据检查约束来源与完整性，不是自动语义判题，示例或猜测不能当作真实 flag。

目标尚未达到时，模型普通文字结尾仍只是阶段检查点。压缩后重新注入当前研究状态，保留证据、失败路线和下一步，继续选择有信息增益的实验；重要决策、可复用失败路线或长任务阶段转换时才简短更新研究摘要。中断后可继续会话，不自动重放工具副作用。连续三次结束检查没有新增工具证据会标记停滞；具体外部阻塞需要说明恢复条件，未得到 flag 本身不构成阻塞。

工具输出先规范 UTF-8 再写入研究摘要；旧版因编码替换导致超长的摘要，只在完整核对原始捕获后恢复，不修改原始证据或重跑题目命令。历史工具调用缺少返回结果时显示“未返回结果”，不会仅因新一轮开始就一直显示运行中。

过程区按真实会话状态显示模型处理、工具执行、结束、中断或连接状态，并提供呼吸灯、耗时和距上次回传的时间。呼吸灯表示服务报告任务仍在运行，不代表已收到新的模型内容。Bash 卡片可展开完整命令与已返回输出，支持复制和详情加载重试；工具尚未返回时明确等待结果，不模拟实时终端输出。系统减少动态效果设置会停用呼吸动画。

整轮主任务和子任务默认仍共享 200 次逻辑模型请求（包括压缩），不是无限运行。长任务可在启动前设置 `prtseek_CTF_MODEL_CALL_LIMIT=2000`（范围 1–100000），会话概览显示实际限制；Windows PowerShell 使用 `$env:prtseek_CTF_MODEL_CALL_LIMIT='2000'` 后在同一终端运行更新入口，Docker 在 `.env` 配置。时间、轮次、调用预算、用户停止及真实外部阻塞中最先到达者生效。数小时续研已覆盖模拟时钟与协议回归，不代表完成真实数小时解题或保证拿到 flag。
